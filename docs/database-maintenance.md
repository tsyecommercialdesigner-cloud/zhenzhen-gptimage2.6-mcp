# SQLite 备份与升级

运行数据放在本地磁盘。升级前应停止服务并确保没有其他进程占用数据目录；
使用 SQLite backup API 创建一致性副本，不能只复制正在使用的主数据库文件。
恢复时先停止服务，将完整备份恢复到新位置并验证版本与完整性；保留原数据库、
WAL 及图片文件，确认后再切换目录。版本不兼容或数据库损坏时拒绝启动，
不要删除或覆盖原数据。迁移必须在事务内执行，失败时回滚。

升级到 schema v2 时，启动迁移会先校验 v1 校验和及完整性，再通过 SQLite
backup API 在同目录创建带唯一后缀的 `*.v1-backup-*.sqlite3`；迁移在事务内
完成，失败时保留原数据库和备份。旧程序不接受 v2 版本，不能直接降级打开；
回滚需先停止服务、另存 v2 数据及相关图片，再恢复并验证迁移前的 v1 备份。
恢复旧备份不会包含升级后的任务，请先按业务需要保存这些数据。

开发版本升级到 schema v3 时，同样先校验 v2 数据库，并以 SQLite backup API 创建
`*.v2-backup-*.sqlite3`，再以事务迁移清理策略及账本；自动清理默认关闭。
旧版不能直接打开 v3。回滚需停止使用该目录的所有接入和后台，另存 v3 数据库、
相关图片及清理账本，再恢复并验证 v2 备份。备份恢复会回到备份时点，不包含之后
的任务和清理状态；已删除文件也不会仅靠恢复数据库自动出现。v3 尚未发布验收。
