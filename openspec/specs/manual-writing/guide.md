# 说明手册撰写指南

本指南用于编写和维护本项目的成员说明文档。规范性要求见 [manual-writing 规范](spec.md)；工程工作方式见 [engineering-practices](../engineering-practices/spec.md)。README、MANUAL 及 `docs/` 中的实际操作说明应依据项目代码、当前规范、锁定依赖和经核对的验收结果填写，而不是将此指南中的目标误写为已实现事实。

## 读者与文件职责

- 根目录 README 说明项目、最短安装入口及 MANUAL 链接；根目录 MANUAL 面向成员提供完整的安装、配置、使用、升级与排障步骤。
- 恢复、数据库维护及供应商验证等较长资料可放在 `docs/` 并由手册链接；同一详细规则尽量在一处维护。
- 手册使用真实项目名称、入口、命令和兼容范围。未实现、未验证及不适用的内容明确标示，不根据其他项目推断。

## 项目参数表

编写时核对项目名称、真实 GitHub 仓库、已验证的 Release/标签及完整提交 SHA，分别记录发行包名、Python 模块名、MCP 服务名、入口和安装目录。还需核对 Python、uv、FastMCP、MCP 协议、stdio 和各 Host 的实际版本与验证状态；各项版本不能相互推断。

本项目 Windows 默认安装目录为 `D:\MCP\zhenzhen-gptimage2.6-mcp`。成员可按实际环境指定其他路径，安装、启动、Host 配置和 `.env` 示例须保持一致；服务名与目录名分别核对，不对路径或版本号做全局替换。

后端密钥变量为 `ZHENZHEN_GPTIMAGEGEN_API_KEY`，只写变量名和设置方法，不写真实值。当前入口未显式指定 `--config-dir` 时使用进程工作目录；在此差异修复并验证前，手册应指导 Host 显式提供实际项目绝对路径，不能宣称已自动固定定位。

## MANUAL 十节

1. **环境准备**：使用者、支持平台、依赖版本、网络、仓库访问、Host、凭据与权限。
2. **项目初始化**：实际 GitHub 来源、已验证 Release/标签及完整 SHA、目标目录、锁定安装和首次配置。
3. **可用性测试**：真实存在的检查入口、命令、超时、退出码和预期结果；区分协议和真实业务。
4. **客户端配置**：适用 Host 的 stdio 配置、作用域、添加或合并、启用、重启与工具发现；说明单数据目录单实例及多目录历史隔离。
5. **启动排障**：使用既有环境的启动方式、stdio 与 stderr、更新、重装及回滚步骤。
6. **文件清单**：区分源码、锁和共享配置与本机生成的依赖、图片、数据库和缓存；说明实际入口和 Release。
7. **资源清单**：依据源码和实际发现列出 Tools、Resources、Prompts、模板、参数、返回与错误；不存在或 Host 不暴露的类别如实说明。
8. **功能说明**：提示词、单次/批量、同步/适用异步、查询、落盘和恢复；区分 GIF 首帧和动画原件、SVG 矢量、尺寸不符及已验证组合。
9. **注意事项**：凭据与目录权限、费用、供应商、限制、超时、取消、幂等、重试、预览和网络边界。
10. **常见问题**：仓库或标签、依赖和入口、锁文件、配置、Host、认证、尺寸、超时与协议输出污染等问题，给出安全且可执行的排查。

## 安装、配置和升级

- 使用项目实际 GitHub Release 的已验证标签与完整 SHA；不存在时注明状态。独立环境执行 uv 锁定运行依赖安装；日常启动复用已准备环境，不在启动时安装、升级或拉取代码。
- 只提供空密钥 `.env.example`；首次配置保留已有 `.env`，限制其文件权限。仅在文件或字段缺失时从 `.env` 回退至进程环境再至 Windows 用户级环境；已定义的空值、非法值、重复或文件读取/解析错误须失败，不回退。错误与示例不包含秘密。
- 后端密钥与 Host 自身认证、codeproxy 或其他对话模型服务分开说明。修改凭据后重启实际 MCP 进程；不擅自修改用户环境变量或其他 Host 设置。
- 升级前记录版本，检查本地改动与冲突，保留 `.env`、权限、图片、数据库和私有配置；切换后重新安装锁定依赖并验证。回滚需要检查 SQLite 兼容和经过验证的备份恢复，不能假设回退代码会回退数据。
- 调用结果未知时先通过本地任务或已保存远程 ID 查询和恢复；不能将超时或取消当作供应商取消，也不能直接重复收费生成。

## Host 与能力验收

对 Codex Desktop、Claude Desktop 和 DeepSeek Harness Desktop，分别记录实际客户端版本、配置、连接、工具发现、会话调用、结果定位及适用图片展示；其中任一环节未测或失败都不能由其他 Host 替代。

Host 的模型渠道不限定为官方 API Key，可使用 Host 支持且已配置的 codeproxy 或其他服务；必要时使用 Windows Sandbox，但须在隔离环境中实际运行目标 Desktop 并完成真实会话调用。Host 的对话模型服务和本 MCP 的 t8-star 图像服务分别记录，真实生图遵守适用授权并注明费用及结果。

示例按实际 Host 和适用 Shell 核对；保留无关服务、登录和配置。JSON 必须是可解析的严格 JSON，YAML/TOML 按实际格式书写；所有示例与实际 Schema、参数、服务名、安装目录、传输和认证一致。手册可以在确有必要且适用于目标客户端时说明配置文件位置，不设置一律禁止列出目录的规则。

## 发布与维护检查

项目通过 GitHub Releases 发布，成员不需要 ZIP 分发；不要求 ZIP 白名单、打包脚本或解压验收。Git 仓库按用途跟踪源码、测试、安全 fixtures、锁、OpenSpec、共享文档和实际工作流；Release 及实际资产关联版本、完整提交和验证结果，并独立检查内容，不能用 `.gitignore` 代替发布物检查。

每次手册受影响时核对链接、配置示例、工具参数、源码和规范；影响安装、启动或 Host 流程时在隔离环境验证相关步骤。分别报告静态检查、隔离安装、协议、Host 和真实供应商验证的通过、失败、不适用或未验证；不因文档工作自动修改真实 Host、读取真实密钥或发起收费请求。

验收结论写入版本控制文档；真实验收原件及脱敏账本保存在 Git 忽略的 `.cache/`。分类清理本次创建且不需保留的测试缓存和临时产物，不能删除用户数据或应保留证据；清理失败记录位置和原因。
