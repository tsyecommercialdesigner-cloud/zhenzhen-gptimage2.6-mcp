# shared-local-backend Specification

## Purpose

使同一数据目录能够安全地被多个本地 stdio MCP 接入进程使用，由唯一后台协调任务、持久状态和结果，避免重复启动导致服务不可用或重复收费。

## Requirements

### Requirement: 共享后台与唯一所有权
系统 SHALL 允许多个 stdio 接入进程连接同一数据目录的唯一活动后台，并由该后台独占调度与数据目录所有权；并发启动不得创建两个活动后台。

#### Scenario: 同时启动接入进程
- **WHEN** 两个接入进程同时使用同一数据目录启动
- **THEN** 两者均可连接同一后台并发现工具，且只有一个后台负责该目录

### Requirement: 有界安全的本地通信
系统 SHALL 仅允许本机获授权的同一用户进程连接后台，校验数据目录身份、协议与运行配置兼容性；对不兼容或不可验证的后台明确报错，不启动第二个后台争用目录，诊断不得泄露密钥。

#### Scenario: 配置或版本不兼容
- **WHEN** 新接入进程发现已有后台的配置身份或协议版本不兼容
- **THEN** 明确拒绝连接并提示安全关闭或升级，不使用另一套配置悄悄接管

### Requirement: 连接中断与后台恢复
系统 SHALL 区分接入进程断连和后台故障；调用响应不确定时不得自动重放有副作用的请求，提供通过原幂等键或任务 ID 查询的方式。后台异常退出后再次连接 SHALL 由唯一后台执行持久状态恢复，再接收新的生成请求。

#### Scenario: 客户端断连
- **WHEN** 生成请求已被后台接收但接入进程断开
- **THEN** 后台保持任务状态，其他接入进程可用原幂等键或任务 ID 查询，不自动重复提交

#### Scenario: 后台中断后重启
- **WHEN** 后台在远程提交结果未知或已有远程任务 ID 时异常退出
- **THEN** 新后台按既有恢复规范处理，未知提交不自动重发，已知远程 ID 查询原任务

### Requirement: 后台关闭与兼容
系统 SHALL 在无接入连接且无未完成任务时有界退出，或由明确的管理操作有序停止；用户现有数据库、图片和配置可被兼容版本使用。后台运行期间不允许旧版单实例服务同时使用该目录。

#### Scenario: 接入进程全部退出但任务未完成
- **WHEN** 最后一个接入进程退出而后台仍有未完成任务
- **THEN** 后台继续负责任务及持久化，不因连接消失丢弃任务或重发请求
