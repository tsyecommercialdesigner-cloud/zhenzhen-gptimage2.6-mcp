# Design

## Context

发布版 `ProtocolResult` 的文本成功时仅为“完成”，其业务数据在 `structuredContent`；DSH 0.2.1-rc.5 本机桥接代码的 `createOutput.render` 从 `content` 取文本，图片经附件存储投影。实测模型可描述 JPEG 附件但 UI 显示“图片无法预览”，生成原件 PNG 已落盘；无法仅凭此断言 Host UI 失败的具体根因。Claude Desktop 服务日志明确显示 `data directory is already in use`；既有 Desktop 子进程持有同目录，使用相同配置启动第二进程可复现错误。

## Goals / Non-Goals

**Goals:** 为文本消费 Host 提供完整结果与原件定位；隔离诊断实际预览链路；指导 Claude 避免重复连接占用同一目录。

**Non-Goals:** 不移除单目录单实例锁，不修改 DSH 上游或将附件副本标为原件，不重发未知结果的收费请求。

## Decisions

### ADR-001：结果文本与结构化结果一致

对 MCP 结果的公开字典进行 JSON 序列化作为文本内容，结构化数据和 `isError` 保持不变，图片仍使用既有 JPEG 内容块。不要输出 `_preview` 或密钥。既有分页和输出资源限制继续适用；测试成功、错误、图片及非 ASCII 内容。相比仅加入路径，完整结果能同时修复能力查询、任务查询和错误信息缺失。

### ADR-002：保留目录锁并避免配置重复

核对 Claude Desktop 的不同配置来源及已运行实例；使用不同目录或移除重复注册的操作由用户确认并应用，不能绕过锁或删除数据。示例和手册说明初次配置与启动验证。仅在真实日志及重启后的会话调用中确认解决。

### ADR-003：预览问题证据优先

使用现有已保存图片与只读 `get_image`，分别观察 MCP 图片内容、DSH 附件投影、模型回复 Markdown 和 Desktop 渲染。实测模型将无扩展名的 DSH 附件副本路径用于 Markdown，而本机文件服务按扩展名确定 MIME，未知类型为 `application/octet-stream` 且设置 `nosniff`；改用有 `.png` 扩展名的已保存原件路径后会话可见图片。工具说明指导区分原件与附件，静态图片在支持本地链接的 Host 可使用原件路径展示；GIF 及 SVG 的预览和原件区别保持既有规则。发布版自动使用结果路径的行为仍须真实会话复测。

## Risks / Trade-offs

- [文本重复结构化内容可能增加体积] → 维持现有限额，测试大结果与脱敏。
- [修复未进入已发布版本] → 发布及安装须经授权并核对版本、数据保留；真实 Host 验收只对已发布版本成立。
- [DSH UI 或模型的展示行为不可控] → 记录证据并保留未通过状态，必要时分离上游问题。

## Migration Plan

先完成本地修复和无收费回归，准备并发布新版本，再在已配置的发布安装目录升级；保留配置、SQLite 和图片。Host 配置如需改动，由用户按说明应用并重启后复测。
