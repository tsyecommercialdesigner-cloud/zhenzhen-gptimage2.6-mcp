# Design

## Context

见 [proposal](proposal.md)。当前后处理先写图片文件，再按尺寸判定是否登记。GIF 已有待确认记录，普通静态图没有对应记录。恢复重走同一后处理流程，图片异常可能落入通用参数错误分支。结案释放队列容量，且会阻止常规恢复。

## Goals / Non-Goals

- 让 Agent 从即时工具响应判断何时查询、恢复、请求确认或停止。
- 维持任务状态、图片登记及恢复证据在共享后台中的一致性。
- 保持模型路由、生成尝试预算、GIF/SVG 规则及保留策略的既有边界。本地找回覆盖尚存的文件。

## Decisions

### ADR 1：区分输入、提交与结果阶段

保留现有响应外壳，以结构化诊断补充任务 ID、阶段、原因、是否能重试同一恢复操作及建议动作。尺寸不符使用 `SIZE_MISMATCH`，包括请求宽高及每项实际宽高。下载、解码、文件异常和状态冲突分别映射到安全原因，避免将业务异常吞入通用参数校验。旧字段保留，批量返回继续逐项报告并提供候选和失败原因，即使外层成功也可区分结果。同步维护发现结果、能力和指南，结构化证据记录渠道、模型、格式、尺寸及参考图范围，未记录的维度不推断。

### ADR 2：有效静态图以实际尺寸交付

静态图完整通过下载、解码、资源限额及落盘验证后，登记供应商返回的原始字节和实际宽高。任务记录保留请求宽高。查询时由两份已持久化尺寸计算差异，在任务上返回 `size_mismatch.code=SIZE_MISMATCH`、请求和逐图实际尺寸，并在单图、批量和查询响应中带上提示。批量以任务为单位计入成功。旧开发版已暂存候选可通过恢复重验并登记，保留历史确认工具兼容旧调用。已结案任务继续使用独立找回流程。

### ADR 3：从已结案任务导出已有文件

提供只读候选检查与单独的恢复导出入口，输入使用任务 ID、图片索引、摘要和目标路径。复用正常导出的托管路径与身份检查、摘要比对、临时文件及无覆盖发布，避免暴露通用任意文件读写。检查禁止沿符号链接或重解析点读取托管目录以外的文件，实际复制绑定同一文件内容。核对清理记录，并沿用与清理互斥的保护，拒绝已清理条目。找回即使成功也只记独立审计事件，维持 closed、计数和原幂等记录。

有历史摘要的候选先比对摘要。对旧版无登记案例，从任务、落盘阶段事件、完整响应证据和程序确定的输出槽位建立归属，验证文件格式及限额。若响应嵌入了原始图片，可与其摘要比对。仅含 URL 的响应无法认证现有字节，文件须标为旧候选，显示当前摘要并取得用户对具体候选的确认后才可复制。文件名本身不构成归属证据。放弃将 closed 改回活动状态的方案，以维持队列、历史和幂等语义。

## Risks / Trade-offs

- 旧原件可能已经被清理、缺失或无法证明归属。工具报告证据缺口，保留现有记录。
- 路径替换、确认竞争或清理竞争可能发生在预览和复制之间。执行时在锁内重验，在发布前检查实际复制字节。
- 兼容旧 Host 的 Schema 表达可能受限。保持既有工具调用形状，以字段描述和可执行示例补充条件约束，并通过三个 Host 实际会话验证。

## Migration Plan

先备份 SQLite，使用增量迁移添加诊断和候选元数据，保留已有图片、任务、GIF 确认、清理与幂等记录。历史任务按需读取证据，不批量重新登记、联网或改状态。在升级副本验证旧数据与迁移，回滚使用兼容版本或按升级流程恢复一致性备份，保留升级期间新增文件及审计记录供核对。
