# Design

## Context

见 [proposal](proposal.md)。现有路径以固定六型号、不可变快照、SQLite WAL、最多 20 项未完成任务、6 并发和入队起 600 秒预算为基础。仅接入 t8-star；截图仅供数据模型参考。用户新增 t8-star GIF 异步提交、查询及远程 ID 恢复范围。

## Goals / Non-Goals

**Goals:** 新增指定格式生成、GIF 动画完整保存、SVG 安全验证及 t8-star GIF 异步状态恢复，保持旧调用和旧数据库兼容。

**Non-Goals:** 不把未确认组合宣称为支持、不做自动跨供应商降级、不改变未指定新格式的旧请求行为、不承诺所有 Host 能播放动态预览。

## Decisions

### 1. 接口与证据边界

2026-11-10 另行验证：t8-star `gpt-image-2.6-flare` 的一个 GIF 组合支持 `?async=true` 并可通过 `/v1/images/tasks/{task_id}` 查询至成功，详见 [实施验证记录](implementation-validation.md)。该实测不证明其他组合可用；本期异步只开放 images 通道、flare 基础型号的 GIF，默认仍同步。

补充 [异步验证矩阵](t8star-async-matrix-20261110.md)：Flare/Sunburst 的部分静态图及 Flare SVG 也成功，但 Chat 未返回任务 ID，部分型号失败或结果不明；全局异步优先的前提尚未满足。本期不以局部成功扩展未验证组合或宣称全通道可用。

SVG 暂只允许路由至已验证的 `gpt-image-2.6-flare` 基础型号；Sunburst 的同步和异步 SVG 均提示缺少绘制模型，不得宣称其不支持 SVG，也不得自动切换型号。非基础 Flare SVG 在提交前拒绝。

- 现有 `https://ai.t8star.org/v1/images/generations` 是同步接口，原有 images/flux/chat 行为不变。2026-11-10 使用 `gpt-image-2.6-flare` 直接探测：`output_format=gif,size=512x512` 返回 `data[0].url`，下载为 816×816 GIF、9 帧、各 200 ms、loop=0；这说明该组合可返回动画，但不满足现有精确尺寸约束。两次 SVG 请求分别不带 `n` 和带 `n=1`，均 HTTP 400，第二次提示缺 SVG 绘制模型；未传 `svg.model`，不能推断 SVG 不支持。3 次已发送，授权上限 4 次（SVG 最多 2、GIF 最多 2），账单未核对。脱敏账本位于 `.cache/svg-gif-contract-20261110/ledger.jsonl`，会被 Git 忽略。
- 本项目以用户此前提供的 t8-star 契约为准：Generations/Flux 同步使用 `POST https://ai.t8star.org/v1/images/generations`，Chat 使用 `POST https://ai.t8star.org/v1/chat/completions`；截图内的其他路径不作为 t8-star 路径或开启远程轮询的依据。截图只提供字段、类型及格式限制的参考，字段序列化和上游行为仍须对目标接口核实。
- 用户提供的数据模型参考包含 `model`, `prompt`, `output_format`、`size`、`n`；GIF 的 `frame_count` 为 2–16、默认 9，`frame_duration_ms` 默认 200 且最小 20、10 ms 步进；SVG 使用 `n=1` 和绘制模型 `gpt-5.4-mini`。GIF/SVG 仅文生图，尺寸限制详见 1.2；该数据模型用于本项目的输入设计，不改变 t8-star 的既有接口路径。对目标接口未经验证的参数映射和结果明确标示为未实测。
- t8-star 为新旧格式的默认供应商，继续使用 `ZHENZHEN_GPTIMAGEGEN_API_KEY` 及既有配置优先级；`output_format=gif` 已实测，但实际尺寸不同于请求。SVG 的 `gpt-image-2.6-flare`、1024×1024、`svg.model=gpt-6-luna` 组合在该端点已实测返回 SVG URL，详见 [供应商验证](t8star-svg-validation.md)；其他尺寸、型号和绘制模型未据此视为通过。不能把另一服务的型号、路径或响应结果自动当成 t8-star 的实测证据。

### 1.1 用户提供的参数契约与实施边界

下表为用户提供的共享参数说明，不代表逐项已通过 t8-star 实测。线上的默认值、枚举、格式组合和字段在具体端点的映射须记录证据；不能把另一服务的限制强加为 t8-star 已确认事实。模型为必填 `model`，提示词为必填 `prompt`；在旧数据模型中先保留单任务单结果及现有参考图约束，不扩大生成数量或上传能力。

| 字段 | 用户提供的类型、范围或默认值 | 本变更处理 |
| --- | --- | --- |
| `model`, `prompt` | string，必填 | 通过当前系列与型号路由、冻结提示词生成；旧通道与新格式的型号能力分别验证。 |
| `images` | URL 数组，最多 16 | 参数资料保留；既有本地 PNG 参考图和 URL 输入的映射未获验证，SVG/GIF 参考图组合默认提交前拒绝，不能静默丢弃；不在本期自动上传公网素材。 |
| `n` | number，1–4，默认 1 | 本期固定单结果 1；SVG 必须为 1，不改变批量任务语义。 |
| `size` | 可选 string，最终转换成比例；建议 `aspect_ratio` | 客户端接受 `auto`、比例或 `WxH`；比例发送为 `aspect_ratio`，auto 省略尺寸字段，像素值发送为 `size`。实测可能返回不同像素，遵循第 2 节。 |
| `resolution` | `1k`、`2k`、`4k`，默认 `1k` | 保留为契约及未来映射信息；精确像素尺寸时不发送，具体路由经核实后支持。 |
| `quality` | `auto`、`low`、`medium`、`high`、`xhigh`、`max` | 纳入格式参数设计；未经确认的组合不宣称可用，不静默变更值。 |
| `output_format` | `png`、`jpeg`、`webp`、`gif`、`svg` | 本期新增显式 `gif`、`svg`；旧静态请求默认及支持情况不变，按实际内容验证格式。 |
| `output_compression` | 0–100，JPEG/WebP 可选，PNG 留空 | 记录约束；SVG/GIF 不传此字段；其余静态扩展不属于本期新增能力。 |
| `background` | `auto`、`transparent`、`opaque`；JPEG 不支持透明 | 记录契约；仅在字段与模型组合被确认并明确支持后允许发送。 |
| `moderation` | `low`、`auto`，默认 `low` | 记录契约；未指定时不擅自覆写既有供应商策略。 |
| `complexity` | `high`、`medium`、`low` | 记录契约；仅在映射及支持范围确认后开放。 |
| `frame_count` | 2–16，默认 9 | GIF 参数；本次 t8-star 缺省返回 9 帧，不证明可控范围全部已实测。 |
| `frame_duration_ms` | ≥20，按 10 ms 递增，默认 200 | GIF 参数；仅缺省 200 ms 已实测，其他值需验证。 |
| `mask_url`, `markup_url` | PNG 图层与第一参考图对齐，二选一 | 记录契约；蒙版/标注编辑不在本期，显式传入则拒绝，不静默忽略。 |
| `svg.model` | 必填，参数资料示例为 `gpt-5.4-mini` | t8-star 已验证嵌套对象及 `gpt-6-luna` 的一个成功组合；`gpt-5.4-mini` 未获成功验证，不默认推断可用。 |
| `svg.reasoning.effort` | `none`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max` | 参数资料记录为可选，具体嵌套结构和支持范围未实测；仅验证后开放。 |

参数表中的范围和默认值属于用户提供的契约，t8-star 现有 OpenAI 格式接口并未逐项证实字段传递或响应行为。记录已知限制和实测范围，不将参考数据模型当成实测。

### 1.2 用户提供的 Sunburst GIF 与 SVG 限制

用户提供的 `gpt-image-2.6-sunburst` 说明将尺寸定义为 GIF **单帧**尺寸，`auto` 默认 512×512，自定义宽高须是 16 的倍数；帧数 2–16、默认 9，每帧时长默认 200 ms、最短 20 ms 且以 10 ms 为步进。按帧数构造拼图时，2–8 帧为 4×2、9 帧为 3×3、10–12 帧为 4×3、13–16 帧为 4×4，行列可互换；拼图每边 ≤3840、面积 ≤8,294,400 像素、长边与短边之比 ≤3。应分别检查两种排列，只要一种满足全部约束即通过该排列检查；超限时发送前提示缩小单帧或减少帧数。每段 GIF 按整张拼图用量结算，实际费用以供应商账单为准。

边界示例：4 帧、120 ms，768×512、1024×512、960×960 满足上述拼图限制；1024×1024 在 4×2 的长边为 4096，超出 3840，因此拒绝。SVG 画布可为 auto、比例或像素值；自定义宽高为 16 的倍数，每边 ≤3840，总面积 655,360–8,294,400 像素，长宽比 ≤3，单次一张。512×512 因面积低于下限而拒绝；1280×768 和 1536×1024 为合规示例。GIF/SVG 只接受文本，参考图、蒙版或标注层必须在提交前拒绝；静态图片所述最多 16 张参考图及蒙版、标注二选一属于提供方契约说明，不扩大现有项目支持范围。

用户明确要求上述截图仅作数据模型参照；提交和查询路径以此前提供的 t8-star 契约为准，不采用截图中的单数路径。上述参数规则作为默认路线的输入设计与边界测试依据，但不表述为已在 t8-star 的复数路径上逐项实测通过。局部解码和文件安全限额仍独立适用，供应商请求合法不代表一定低于本地资源限额。

### 2. 用户接口、快照与兼容

扩展既有请求以添加显式 `output_format`（旧请求缺省映射到原行为）、GIF 帧数/帧时长、执行模式及 SVG 绘制模型配置；参数只对对应格式有效。t8-star 默认同步，已验证组合可显式异步。用户继续以 `family` 选择 flare 或 sunburst。明确生成任务 ID、格式、实际宽高、文件类型、GIF 帧数/时长/循环、警告和文件路径。

默认精确尺寸策略为严格：请求精确宽高而 GIF 实际尺寸不符时，验证并原样原子落盘原件，记录实际尺寸、摘要、帧和时长，保留响应与文件，任务进入 `recovery_pending`，返回尺寸不符警告和可访问的待确认原件信息，不缩放、不重发。新增显式本地确认操作，用户在检查预期状态和实际尺寸后接受该结果，原子登记并使任务成功；确认必须幂等并持久化审计，不调用远程生成。用户也可在首次提交时显式选择接受实际尺寸策略，该策略冻结进快照和幂等摘要：有效 GIF 可直接成功并返回尺寸警告。两种策略都不能接受损坏、静态或错误格式。对 auto/比例请求报告实际尺寸，不伪装为精确尺寸保证；用户显式确认如何处理比例不符前不得默默认为符合。旧静态格式的尺寸规则不变。

新增字段纳入新请求的输入摘要和不可变快照；版本化摘要与快照解析，显式维持旧任务缺省输入的旧摘要算法，保证升级后的同键复用及未完成任务恢复，旧记录不可被重算覆盖。带相同键而供应商、格式、尺寸策略或帧参数不同必须冲突。模板展开后依旧冻结内容。

### 3. 状态、并发与恢复

请求增加 `execution_mode`，默认 `sync`；`async` 仅对 images、基础 flare 的 GIF 开放，其他组合在提交前拒绝。新异步值纳入摘要和冻结快照；同步默认不改变现有摘要，以便旧任务复用。

异步生成向现有复数路径 POST `?async=true`，接收顶层 `task_id`，原子写入现有 `remote_tasks` 扩展表，然后通过 GET `/v1/images/tasks/{task_id}` 查询。识别 `NOT_START`、`SUBMITTED`、`IN_PROGRESS`、`SUCCESS`、`FAILURE`；成功时保存内部 `data.data` 作为原响应并沿用现有 GIF 处理；未知状态或查询失败不得重发 POST。响应到持久化之间崩溃且无法取得 ID 标记 unknown。已保存 ID 的任务重启后继续查询相同 ID，不增加提交尝试。远程状态、任务 ID 和并发占用必须持久化，未知终态时保守占用额度，禁止超过 6 个远程在途；不以本地等待超时假定远程停止。停止时保留 ID，30 秒后停止请求并完成必要落库。

对远程提交先事务记录尝试，再发送；收到响应后持久化响应，不持久化密钥。提交结果未知时标记 unknown，禁止重复 POST。远程失败按确定语义分类，禁止无证据的自动重试和切换；结果下载不增加生成尝试数。

沿用全局 20 未完成容量、6 个完整任务并发、600 秒从接收入队起的任务期限和最多 3 次明确安全的生成尝试。服务停止沿用 30 秒等待宽限期，必要落库与关闭可继续完成。

### 4. 安全验证、原件与预览

按请求格式验证实际内容而非扩展名或 Content-Type；保留既有下载和原子落盘流程，GIF 原始字节写 `.gif`、SVG 原始字节写 `.svg`，计算并核对 SHA-256。GIF 至少两帧，逐帧完整解码并记录画布尺寸、帧数、时长、loop；拒绝损坏及超限输入，验证不重新编码、不覆盖原件。GIF 限额建议：最多 16 帧、每帧及总解码像素上限分别为 8,294,400 和 33,554,432，文件最多 32 MiB，持续使用既有任务预算和受控解码并发；超过时不部分成功。

SVG 使用安全的 XML 解析及受限元素/属性白名单，禁止 DTD、实体、脚本、事件处理器、外部 URL、foreignObject、嵌入式栅格及会触发外部加载的 CSS；限制原始文件 8 MiB、节点数 100,000、嵌套深度 128、声明画布尺寸与资源使用；无法确定的尺寸、SVG 或 CSS 安全语义拒绝，不运行远程内容。数字宽高或可解释的 viewBox 作为有效画布依据，保证符合限制。SVG 可缩放但报告其画布尺寸，不能用栅格图片冒充 SVG。

预览不改变原件。GIF 可生成标记为静态的首帧 JPEG 预览；SVG 若没有可靠沙箱渲染器则只返回路径/元数据及预览不可用提示，不将未净化 SVG 注入 Host。两者仍遵循最多一张、长边 1024、编码后 ≤1 MiB 的预览预算。后续如支持动画预览，应单独验证 Host；原件保帧是必需能力。

### 5. SQLite 与迁移

实施受版本管理的迁移：保留旧快照和摘要，增加格式状态、帧元数据及必要迁移约束。现有 tasks 的尺寸 CHECK 经受控重建以允许 auto 和比例，扩展表保存新字段；不得绕过外键、WAL、单实例锁和一致性备份。已创建的保留表不删除或修改迁移校验和。变更前备份，升级后校验旧任务、模板、原图与幂等；禁止旧版本直接重写不兼容数据库，采用受检备份恢复且保留新数据。

## Risks / Trade-offs

- [供应商响应尚未逐项核实] → 区分用户参数说明和实测范围。
- [远程提交结果未知] → unknown，保留证据，不自动生成第二次。
- [尺寸和帧预算高于静态图] → 限制帧数、解码像素、磁盘和任务期限，返回明确错误。
- [SVG 可携带主动内容] → 严格安全校验，默认不渲染到 Host；不以简单扩展名或 XML 解析成功代替安全判断。
- [旧任务幂等变化] → 摘要算法版本化，迁移回归覆盖原 SQLite 快照及进行中任务。

## Migration Plan

实现可回滚迁移与 t8-star 适配；离线测试与干净环境回归；在授权范围内做 t8-star 真实 SVG/GIF、恢复及 Host 验收。发布前备份 SQLite 并记录回滚版本。
