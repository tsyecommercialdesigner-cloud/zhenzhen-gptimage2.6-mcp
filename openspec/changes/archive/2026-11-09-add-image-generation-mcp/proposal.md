# Proposal: zhenzhen-gptimage-2.6-mcp

## Why

电商运营人员及其他 Agentic 工具使用者需要在日常会话中完成用图需求表达、提示词优化、图像生成和结果保存，减少在 Agent、远程图像服务与本地文件之间的手动操作。为 Claude Code、Codex、DeepSeek Harness 提供统一的本地 MCP 图像能力，使单个及批量生成任务可提交、可查询、可恢复，并可持久化到本地磁盘。

## What Changes

- 新建本地 stdio MCP Server，通过 MCP Tools 提供图像生成任务操作，通过 Resources / Prompts 为 Agent 提供电商提示词优化指引；提示词优化由 Agent 结合用户诉求、商品事实与参考图完成。
- 将优化后的提示词及用户附带的参考图提交至远程 API，仅要求同步图像生成；支持通过 `POST /v1/images/generations` 和 `POST /v1/chat/completions` 两类端点生成图片，接口格式优先级为 Generations → Flux → Chat Completions，提供本地任务状态查询及结果解析能力。参考图的具体传输格式依据各通道的图像契约确定。
- 增加尺寸路由能力：按画布长边在所选 flare/sunburst 系列内选择基础、2k 或 4k 型号，路由结果在入队前冻结；规则见 `design.md`。
- 支持单个及批量任务提交：每次批量最多 20 个图像生成请求；整个队列最多容纳 20 个未完成任务，排队与执行中的任务共同占用容量；容量不足时明确反馈，不静默丢弃任务。
- 提供本地任务队列管理与有界调度，最高支持 6 个并发提交。具体并发槽位生命周期及同步请求与本地任务状态的映射在设计阶段确定。
- 将生成图片及关联结果信息保存到本地磁盘，并通过 MCP 返回可供 Host 渲染的图像内容；将 Codex 当前会话中的图像展示列为实际验收目标。
- 提供本地图像生成历史查询，可追溯任务状态、生成结果及本地文件位置。
- 支持将常用提示词保存为模板，浏览与查询模板，并通过快捷代号调用模板用于生成任务。
- 持久化任务状态，支持运行意外终止后再次启动时恢复状态；提供本地幂等机制，避免同一逻辑请求被重复入队或重复提交。对于远程是否受理无法确定的任务，不将本地幂等等同于远程恰好执行一次；对账及恢复策略根据 API 契约设计。

### 本期边界与技术约束

- 不做复杂认证鉴权或企业级治理；远程服务所需的基本凭据配置仍属于必要接入范围。
- 使用 uv 管理依赖与运行环境，Python 固定为 3.12.14，使用 httpx 的异步 I/O 实现并发 HTTP 通信；该实现方式不代表供应商提供异步图像生成模式。
- 每个逻辑任务的总期限为 600 秒，覆盖排队、重试与保存，具体超时口径见 `design.md`。
- API 密钥变量名固定为 `ZHENZHEN_GPTIMAGEGEN_API_KEY`，默认优先读取 `.env`，兼容进程及用户级环境变量；不持久化密钥至任务数据。
- 运行方式为本地 stdio MCP Server。本期不引入远程 MCP 服务部署或独立 Web 管理界面。
- 远程 Provider 为 `t8-star`，基础地址为 `https://ai.t8star.org`。目标模型为 `gpt-image-2.6-flare`、`gpt-image-2.6-flare-2k`、`gpt-image-2.6-flare-4k`、`gpt-image-2.6-sunburst`、`gpt-image-2.6-sunburst-2k`、`gpt-image-2.6-sunburst-4k`；这是用户指定的接入范围，尚未实测各模型的接口兼容性。
- 已提供通用 `POST /v1/images/generations`、同路径 Flux 示例及 `POST /v1/chat/completions` 工具调用契约。Generations 请求定义了必填 `model`、`prompt`，以及可选 `size`、`aspect_ratio`、`image` 字符串数组，但未定义图像响应结构；参考图仅注明部分模型支持。Flux 示例不构成新增 Flux 模型支持范围，也不能据此推定上述六个模型的参数能力。
- 根据用户确认，上述六个目标模型均不支持供应商原生异步模式。本期移除异步生成模式及远程任务结果轮询要求，不引入远程异步提交或轮询端点；保留本地队列、状态查询、历史及重启恢复要求。
- Chat 通道已明确纳入图像生成范围。用户提供的请求使用 `gpt-4o-mini` 和天气函数，返回为 `choices[].message.content` 中的普通文本，属于通用函数调用请求与文本响应示例，尚未定义六个目标模型的参考图输入及生成图片输出格式。其 `tools`、`tool_choice` 和采样参数类型仍存在 schema 与示例不一致，不能直接用于生成可靠的图像数据模型，也不将示例中的天气函数或 `gpt-4o-mini` 纳入产品能力。
- Generations 请求示例展示了 `model`、`prompt`、`size`、`aspect_ratio` 和 `image` 字段；Flux 示例使用 `flux-dev`、`prompt` 与 `size`。此前会话未提供响应；现采用 `references/API-ENDPOINT-GPTIMAGE.md` 中相同 Generations 接口的请求与响应结构作为参考，兼容 `data[].url` 与 `data[].b64_json`。文档的 URL 实测来自 2.5 模型，不代表已实测 2.6。
- 数据模型将依据补充并明确后的接口契约生成；Generations 共享结构已纳入设计；待补充项为参考图字符串编码、Chat 图像输入输出及供应商失败响应。恢复设计须处理同步请求中断后远程受理或完成状态未知的情况，不假定存在远程查询或对账接口。文档中的 Authorization 示例值不写入项目配置或用作调用凭据。

Chat Completions 的尺寸由供应商决定，不支持定制；调用前提示用户，保存并展示实际尺寸。尺寸路由适用于 Generations/Flux。优先级用于调用前选型，不进行失败后的跨通道自动收费重试。

### 验收标准

- [ ] Agent 能利用 Resources / Prompts，结合电商用图诉求及参考图优化提示词，并将其用于生成请求。
- [ ] Codex 能连接本地 stdio MCP Server，完成单个及批量任务提交、查询和本地结果保存。
- [ ] Images 与 Chat 两个通道均可完成同步图像生成、结果解析及落盘；生成图片可在 Codex 当前会话中渲染。
- [ ] 提示词模板可保存、浏览、查询，并可通过快捷代号调用。
- [ ] 单批支持 1–20 个请求；超过 20 个时明确拒绝；多次或并发提交不会使全局未完成任务总数超过 20。
- [ ] 有足够任务时可支持 6 个并发提交，并且不会超过该上限；容量不足时返回明确结果，已接收任务不会丢失。
- [ ] 运行意外终止后，再次启动可恢复已持久化任务状态；重复逻辑请求由本地幂等机制识别，对远程受理状态未知的请求避免盲目重提。
- [ ] 可查询生成历史并定位已保存的结果文件。

## Capabilities

### New Capabilities

- `prompt-assistance`: 通过 MCP Resources / Prompts 为 Agent 提供基于电商需求、商品事实和参考图的提示词优化指引。
- `image-generation`: 通过 Images 与 Chat 两个通道提供提示词及参考图提交、同步图像生成与结果解析能力。
- `task-queue`: 管理单个与批量任务的接收、调度及本地状态查询，约束单批 20 个、全局 20 个未完成任务及最多 6 个并发提交。
- `image-results`: 持久化图像结果与关联信息，提供 Host 可渲染的图像输出及历史查询。
- `prompt-templates`: 管理常用提示词模板，提供保存、浏览、查询和快捷代号调用能力。
- `task-recovery`: 持久化任务状态，支持重启恢复、本地幂等及远程受理状态不确定时的安全处理。

### Modified Capabilities

无。当前项目尚无已有能力规格，本次为初始能力建设。

## Impact

- **项目现状**：仓库已初始化 OpenSpec，目前没有业务代码或测试；用户已在会话及附件中提供部分远程 API 契约，上述行为均为拟新增能力。
- **代码与依赖**：后续实现将新增 Python 项目配置、stdio MCP 入口、远程 API 适配、任务调度与持久化、结果处理及模板管理模块，并引入 MCP 所需依赖和 httpx，通过 uv 固定环境。
- **外部系统**：需要对接远程图像生成 API，本期验收 Codex 的工具调用与输出兼容性，Claude Code 和 DeepSeek Harness 保留为目标 Host 但不作为本期验收要求；当前会话内图像渲染依赖 Host 的实际支持，需要集成验收。
- **本地数据**：将产生任务记录、生成图片、历史与模板数据；具体数据模型、存储布局和恢复机制在接口契约补充后写入设计。
- **后续规划依赖**：Provider、目标模型及已知接口信息已补入提案。明确上述契约缺口后，继续制定 `design.md`、数据模型、能力规格与实现任务清单；当前不代表已具备开始实现所需的完整规划。
