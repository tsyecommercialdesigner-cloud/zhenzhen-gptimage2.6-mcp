# Design

## Context

当前 `mcp_api.main` 在每个 stdio 进程内启动 `running_service`，后者以 `server.lock` 独占目录，初始化 SQLite、恢复、调度与图片落盘。各进程内 `TaskLocks`、队列和恢复流程并不具备跨进程协调能力。Claude Desktop 日志显示 shared-pool 争用该锁；Cowork 会话未发现服务。日志未完全证明所有重复启动路径。

## Goals / Non-Goals

**Goals:** 保持现有 MCP API 和状态数据，单目录单后台，多 stdio 入口可并发连接；后台故障时维持原恢复、幂等和收费安全语义，实际验证 Cowork。

**Non-Goals:** 远程多机服务、绕过单一调度者、实现企业级认证、改变供应商契约或移除队列限制。

## Decisions

### ADR-1：单后台与轻量 stdio 接入

每个数据目录只有一个持锁后台，独占 SQLite、调度器、恢复服务及图片写入；各 stdio 进程只负责协议适配及请求转发。接入进程启动时复用或启动后台。为避免分裂，后台始终持有现有 `server.lock`；旧版进程持锁时新版必须报错，反之亦然。替代方案是每进程独立目录（割裂历史和全局限制）或多调度器共库（跨进程协调难度更高）。不同目录仍各自隔离。

### ADR-2：本地发现、通信与信任边界

使用仅绑定回环地址的本地 IPC（Windows/macOS/Linux 均可运行的 loopback TCP），后台随机端口；握手使用运行时随机令牌，端点信息和令牌放在数据目录内仅当前用户可读写的运行时文件，Windows 需以 ACL 实测，POSIX 使用受限目录与文件权限。无法建立或验证受限权限时拒绝启动；不依赖回环地址本身作为认证。检查规范化目录身份、协议版本、部署版本及不暴露密钥的有效配置指纹；凭据变化导致指纹不兼容时提示有序重启，不记录或返回密钥及令牌。禁止通过命令行传令牌，限制连接数、帧长和请求预算；stderr 日志脱敏，stdout 仅协议。替代命名管道/Unix socket：跨平台实现与权限验证复杂；不得为兼容而降级权限。

### ADR-3：启动选主与故障处理

接入进程先读取发现信息并握手；失败时竞争独立短期启动锁，持锁者再次检查并启动后台，其他进程有界等待并重试握手。后台获取现有目录锁、完成迁移检查与恢复后，再原子发布带随机实例 ID 的发现信息。锁由操作系统释放，不根据 PID 或旧文件存在性杀进程、删除目录锁或认定所有者死亡。发现文件过期时仅在持启动锁且确认独占后台锁后清理；活锁、权限、握手或配置错误应清楚报错。后台启动失败不覆盖既有用户数据，调试信息不得含秘密。

连接和请求有界超时与取消；后台运行期间所有工作由后台持久协调。IPC 响应不明时任何有副作用请求不自动重放；客户端报告不确定并提示用原键/ID 查询；显式重复请求交由持久幂等检查。后台崩溃时下一连接触发重启，先恢复再开放接收；已有异步远程 ID 只查询原任务，未知提交不重发，保留剩余并发预算、期限及尝试次数。后台未完成任务包含 unknown 与 recovery_pending，因而可能长期保留；明确管理停止与运行状态诊断须可用。

Windows Host 可能在断开时主动终止 stdio 子进程的整个后代树；隔离安装演练证实普通 detached 子进程和 `CREATE_BREAKAWAY_FROM_JOB` 均不能确保后台存活。经用户确认，Windows 改用本机 WMI `Win32_Process.Create` 在独立进程树中隐藏启动；已验证 `Win32_ProcessStartup.EnvironmentVariables` 可在内存中传递指定变量，因此使用变量白名单而非持久化凭据文件，覆盖凭据来源和受支持的网络代理、证书与运行环境变量，不记录变量值。WMI 无法启动时明确失败，不回退到会随 Host 关闭而终止的子进程。POSIX 继续使用独立 session。须在真实 Desktop 和隔离安装中分别验证存活、权限、配置继承和收尾。

### ADR-4：生命周期和调用语义

后台与接入连接独立：一个入口退出或 Host 中断不得取消其他客户端或已接收任务；无连接且无未完成任务连续空闲 60 秒后后台有序退出。明确区分 MCP 调用取消和传输断连；取消请求仅按现有业务规则操作，断连绝不隐式取消或重放。后台停止时沿用 30 秒停止接收和等待在途的宽限期，之后不再启动请求，允许必要持久化及资源关闭完成。同步调用断线后用幂等键或任务 ID 取回结果；透明跨进程传递文本、结构化内容、图片、错误及分页，不让后台控制任一 Host 的 stdout。

### ADR-5：兼容与配置身份

保留 `--config-dir`、`--data-dir` 及原默认值，目录中原 SQLite、原件、任务 ID 和模板不搬迁；与既有 schema 不兼容时停止并提示备份恢复，不能重建数据库。不同配置目录、有效密钥、限制、软件或 IPC 协议不一致不得静默复用。若无需数据库变更，保持现有 schema；若实现需迁移，必须另行设计向前兼容与备份、验证回滚。明确 Windows 安装配置与用户已有 Host 配置的合并步骤；如需修改 Host 配置，由用户应用并重启后验收。

## Risks / Trade-offs

- [后台挂起或残留] → 健康检查、有界等待和安全管理停止；不依据过期 PID 杀进程。
- [同机恶意或其他账户连接] → 用户级权限、随机令牌、资源限额、握手验证和权限失败关闭；不承诺抵抗同用户恶意代码。
- [IPC 断开发生在接收之后] → 不重放收费请求，查询原键并恢复持久状态。
- [未知任务长期占用资源] → 明确提示、现有结案规则、管理停止，不释放未知远程并发约束。
- [历史变更交叉] → 与 `fix-desktop-mcp-compatibility`、`add-manual-writing` 联合核对，Cowork 实测通过前不勾选依赖项。

## Migration Plan

先停止所有使用目标数据目录的旧版 Host/服务，备份现有配置和 SQLite（含一致性状态），安装新版本并确认原目录及原件未改变；以多个入口验证同一后台、原历史、恢复和 Host。回滚前有序停止新后台及所有入口，确认旧版本数据库兼容并保留新增数据；不兼容时使用经验证备份恢复，说明恢复时间点后数据的处理。发布后 Host 验收必须使用实际发布安装目录和用户应用的配置，不用开发副本代替。
