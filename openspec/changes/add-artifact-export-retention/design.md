# Design

## Context

参见 proposal。`get_image` 暴露本机路径和可能缩放的预览，Cowork 沙箱不一定能读取本机路径。共享后台持有 SQLite、图片和响应恢复材料，且同一数据目录服务多个 Host。`image_artifacts` 记录原件及摘要，`responses`、`reference-staging` 和待处理文件可能参与恢复。

## Goals / Non-Goals

**Goals:** 原字节导出；可审核且可恢复的清理；维护既有历史、幂等、任务恢复和单后台并发语义。

**Non-Goals:** 任意文件读写、远程存储、视频能力、清除 SQLite 或工作区副本、重发供应商请求。

## Decisions

### ADR-1：后台执行导出

增加 `export_image(task_id, image_index, destination)`，destination 使用服务端本机绝对路径并限定在用户预先明确授权的导出根目录下；不自动信任 Agent 提供的沙箱路径。按登记的文件、格式和摘要复制，创建目录时验证真实路径和重解析点，禁止逃逸；目标默认独占创建、不覆盖。临时文件完成复制及哈希验证后安全发布，返回完整路径、字节数与摘要。源与目标冲突、源缺失、权限错误和跨平台路径不匹配均明确报错，不重生成。相比挂载全部 MCP 数据目录，仅授予可控的导出目的地权限。

Cowork 路径映射必须在真实 Desktop 测试：用户选择的工作区在 Windows 上的实际路径作为授权根，不能把 `/mnt/...` 推断为 Windows 路径；如 Host 未暴露映射，明确要求用户提供或配置真实路径。验证由服务端写入后 Cowork 可在挂载工作区内打开相同文件。工具描述明确此权限边界，扩展名和格式保留，导出不改变托管原件。

### ADR-2：候选清单与权限

`preview_cleanup` 根据日期或保留最新 N 个筛选，排序使用产物创建时间及稳定标识；返回具体候选、摘要、总量、跳过原因和过期时间的计划 ID。`execute_cleanup(plan_id)` 必须由用户在看见计划后明确授权，由 Host 的交互授权或等价的明确用户指令表达；调用参数或模型自行生成的布尔值本身不是用户授权。计划绑定数据目录、候选身份、筛选条件和版本；执行逐项重新检查状态、路径及内容身份，跳过变化项，绝不纳入新项。过期或重启后的计划失效须重新预览和授权。优先安全失败，不以全目录递归删除。

经用户确认，优先采用 Host 可验证的交互确认；Host 不支持时，由用户在本机运行确认命令批准具体计划，之后服务端才可执行。交互不可用或授权无法验证时必须失败关闭，不得把 Agent 提供的标志或文本当作用户确认。

### ADR-3：保留和崩溃一致性

自动策略默认关闭，用户明确启用后持久化策略；后台运行时定期评估生成时间严格早于当前时间减 90 天的候选，用户可查询、关闭。首次启用须明确提示会删除到期原件，不能由默认配置开启。仅处理已完成且无恢复依赖的已登记产物，以及经验证不再为恢复所需的关联文件；未知归属文件、活动任务、待恢复任务、SQLite、配置、锁、模板和导出副本排除。当前产物类型是图片，不以假定的扩展名删除视频。

新增向前迁移的清理账本与产物可用状态，记录计划/策略、文件身份、删除意图、结果、失败及时间；历史数据和幂等记录保留。通过后台统一锁协调导出、清理、读取和任务状态，逐项持久化意图，删除后持久化结果；启动时核对未完成意图的文件存在性和身份，安全恢复，绝不重发生成。数据库与文件系统不能跨介质原子提交，故不以单次事务承诺原子性；遇到身份不明时停止并提示人工核查。导出中的源保持受保护，避免与清理竞态。历史查询明确已清理而非混同外部丢失。

## Risks / Trade-offs

- [删除不可逆] → 预览、具体授权、默认关闭、重检和逐项账本；不以建议或 Agent 参数替代授权。
- [Host 工作区路径不同] → 先验证本机路径及访问映射，失败时提供清晰提示，不自动扩大权限。
- [重解析点及并发替换] → 逐层校验、受限路径操作及执行时重验；平台无法保证安全时拒绝。
- [关闭期间无自动清理] → 下次启动后检查，文档明确不是系统级定时任务。

## Migration Plan

备份 SQLite 与配置，在隔离数据副本验证增量迁移及历史可查询；升级默认自动清理关闭。回滚前停止后台、备份迁移后数据库，验证旧版本兼容性；不兼容时使用备份并说明恢复点之后数据的处理，不静默重建。发布后使用已配置安装版，以既有图片在 Cowork 实测归档和打开，不产生供应商生成费用；清理实测使用隔离合成数据。
