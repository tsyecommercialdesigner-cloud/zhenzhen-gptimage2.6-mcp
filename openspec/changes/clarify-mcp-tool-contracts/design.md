# Design

## Context

`server.py` 以 `TOOL_INPUTS` 的 Pydantic JSON Schema 覆盖 FastMCP 自动生成的 Schema；`GenerationRequest` 的多个跨字段约束在 `model_validator` 中，Schema 不会自动体现它们。部分工具没有 docstring；现有服务分派的 `ValidationError` 被压缩成通用错误，而 FastMCP 自身也可能在分派前拒绝请求。手册含示例，但 Host 不保证读取手册或 Resources。现有能力和验证范围以代码及主规范为准。

## Goals / Non-Goals

**Goals:** 让实际 `tools/list` 返回的契约及本地校验反馈可指导 Agent，保留旧调用的可用性，并用真实 Host 验证。

**Non-Goals:** 不扩大异步、格式或供应商支持范围；不改变工具名称、原有必填字段、数据存储、付费提交与恢复行为。

## Decisions

### ADR 1：单一事实来源与多层描述
为输入模型字段添加说明、默认与约束，在工具 docstring 提供用途和跨字段关系；从现有模型和常量生成或验证能力提示，避免单独维护互相矛盾的手写表。生成、批量、查询、恢复与导出给出精简、可验证的 JSON 参数示例；为其他公开工具提供用途和字段说明。可较长的端到端示例放在 MCP 可读资源及手册，工具描述须足以发现资源且包含关键规则。替代方案是仅改手册，但 Host 不一定读取。

### ADR 2：兼容优先的条件 Schema
对可表达且不改变有效输入集合的规则，评估 `oneOf`、`anyOf`、`if/then` 等 JSON Schema 表达，先测试 FastMCP、MCP SDK 和三个 Host 的解析；不兼容或涉及像素计算、模板状态等复杂语义时，在工具描述明确并保留服务端校验。不能为了使错误发生在客户端而增加未约定限制；使用正反例比对旧、新有效请求集合。分别明确普通图像、Chat、SVG/GIF、参考图、模型路由和当前异步组合的实际边界。

### ADR 3：安全错误分类与双层入口
盘点 SDK 入口和 `dispatch` 的实际验证顺序；以结构化方式映射安全的字段路径、错误类型和固定建议，跨字段规则使用可识别代码映射，未知错误使用脱敏通用回退。不回显用户提供的字段值、动态键名、路径、异常文本、提示词或密钥；保持 `INVALID_ARGUMENT`、`isError` 和 `next_action` 兼容，参数错误不发送供应商请求。对 SDK 在服务分派前返回的错误单独实测，无法统一时记录真实限制，不承诺不可控行为。

### ADR 4：分层验收与避免收费
先通过模型及真实 `tools/list`/`tools/call` 协议测试检验契约、SDK 前置拒绝与错误脱敏；再使用隔离供应商替身验证提交流程和不发生重复提交。三个 Desktop 各自使用发布安装、已配置数据目录与独立测试工作区，优先使用已存在的 PNG 和无效生成请求，观察 Agent 自行构造参数、查询、修正、导出；不得把替身或只读查询称为真实供应商生成。对需验证有效生成参数的实际 Host 会话，可使用独立测试配置和受控替身，单独标明其非发布环境；需要真实收费生成时另申请明确次数与范围。验收前确认已应用配置、服务版本和目录；保留证据并清理本轮临时资源。

## Risks / Trade-offs

- [Host 对复杂 Schema 支持不一致] → 使用真实 Host 逐一验证；必要时将不兼容约束移至说明和运行时，维持语义。
- [详细错误泄露输入] → 使用白名单路径和静态消息，测试恶意键、路径、提示词、令牌和嵌套输入；不得记录原值。
- [Host 无法读取 Resources] → 关键说明和最小示例随工具发现返回，资源只承载扩展说明。
- [测试诱发费用或误报] → 默认不请求真实供应商，替身与真实 Host/供应商证据分别记录，结果未知不重发。

## Migration Plan

现有字段及工具签名兼容，发布前对照前版 Schema 和请求回归。部署按项目已批准的 Release、备份及 Host 联调流程执行；如新描述或 Schema 导致 Host 不兼容，回退代码版本并保留数据库与原件，不能把切换代码等同数据库回滚。
